# 清理与资源治理安全边界

## 核心原则

自动清理的目标是删除“能证明可重建且当前未被使用”的开发产物。容量目标
不会改变白名单。即使磁盘仍低于恢复线，也不会扩大到个人文件或未知缓存。

## 磁盘自动清理白名单

| 类别 | 位置 | 必须满足的条件 |
|---|---|---|
| 大型测试二进制 | `/private/tmp/*.test` | 直接子项、当前用户所有、普通文件、非符号链接、Mach-O、至少 100 MiB、至少一小时未改、未打开、无进程引用 |
| 独立 Go 缓存 | `/private/tmp/<白名单名称>` | 直接子项、当前用户所有、目录、非符号链接、至少一小时未改、结构符合 Go 缓存桶、无 Git 数据、未打开、无进程引用 |
| Go 临时目录 | 当前用户 `DARWIN_USER_TEMP_DIR` 下的 `go-build*`/`go-link*` | 直接子项、当前用户所有、目录、非符号链接、至少一小时未改、无活跃构建、未打开、无进程引用 |
| 共享 Go 构建缓存 | `~/.cache/codex-go-build` 的内容 | 根路径、所有者和真实路径一致，缓存至少五分钟安静，连续两次无构建/打开文件，逐子项再次检查 |

共享缓存只清空其内容，保留根目录。Go 模块缓存
`~/.cache/codex-go-mod` 不在白名单内。

## 永久排除

- `$HOME` 和任意用户目录根
- 项目、源码、Git 仓库和 worktree
- 文档、下载、桌面、照片、视频
- Chrome、Codex、飞书和其他应用数据
- 浏览器缓存和浏览历史
- Go 模块缓存
- 符号链接目标
- 所有者不是当前用户的文件
- 被进程引用、打开或身份无法验证的文件

## 失败关闭

以下情况会跳过候选或整个组：

- `ps`、`lsof` 或真实路径检查失败
- 扫描后文件大小、inode、修改时间或子项数量发生变化
- 新的 Go 构建开始
- 文件在执行前变成打开状态
- 路径出现符号链接、Git 数据或未知结构
- 自动清理或主动清理已经持有共享锁

主动清理计划五分钟后失效。执行时不会相信扫描结果，而是重新完成关键校验。

## 资源治理边界

CPU/内存治理不是通用的“杀高占用进程”。它只可能处理同时满足以下条件的
当前用户进程：

- 可执行文件在 `/private/tmp` 或当前用户 `DARWIN_USER_TEMP_DIR`
- 文件名以 `.test` 结尾且是 Mach-O
- 至少运行 30 分钟
- 父进程为 PID 1，即原调用方已经退出
- CPU 或内存异常连续达到门槛
- PID、创建时间、UID、命令和路径在发信号前仍一致

普通应用、Chrome、Codex、系统进程和安全软件只会进入排行，不会被终止。

## 恢复能力

被清理的数据不进入废纸篓，因此操作本身不可恢复；安全性依靠白名单和执行前
复核。Go 构建缓存可在后续构建中重新生成，代价是第一次构建可能更慢。

项目、模块源码和个人文件不应依赖恢复机制，因为它们不会进入删除范围。

## 修改白名单

扩大路径、放宽类型、取消活跃进程检查或引入新的自动终止对象，均属于安全
边界变更。变更时需要：

1. 给出新对象为什么可重建的直接证据
2. 定义路径、所有者、格式和活跃状态不变量
3. 覆盖符号链接、内容变化、打开文件、进程竞争和异常中断测试
4. 更新本文档、隐私说明和商店披露

不要仅因为希望释放更多空间而扩大白名单。
